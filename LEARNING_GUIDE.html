    Null safety: the most important Kotlin idea

    A type with ? may be null (meaning "no value"). Kotlin forces you to handle that case, which removes a whole class of crashes.

    SyntaxReads asExample
    Double?"a Double or nothing"fun evaluate(...): Double? returns null for invalid input
    ?: (Elvis)"if null, use this instead"evaluate(expr) ?: return ERROR
    ?.let { }"if not null, do this with it"value?.let { NumberFormatter.formatResult(it) }
    .orEmpty()"null becomes empty string"savedState.get<String>(KEY).orEmpty()
    toLongOrNull()"parse, or give null instead of crashing"value.toLongOrNull() in BaseConverter
    Why it matters hereA calculator constantly receives invalid input ("5++", "(", overflowing hex). Mantis represents "couldn't compute" as null internally and converts it to the text "Error" only at the edge, right before display.

    Functions

    • Default parameters: isDegreeMode: Boolean = true lets Basic call evaluate(text) without passing a mode.
    • Named arguments: CalcButton("=", color = MantisGreen, textColor = Color.Black) makes long calls readable.
    • Lambdas: { viewModel.onEvent(BasicCalcEvent.OnEqualsClick) } is a function passed as a value, used for every onClick.
    • Trailing lambda: if the last parameter is a function, it can go outside the parentheses: CalcButton("7", Modifier.weight(1f)) { … }.

    Classes and objects: the six kinds Mantis uses

    class

    A blueprint you create instances of. class BasicViewModel(...) : ViewModel(), where : means "inherits from".

    object

    A singleton: exactly one instance, created automatically. object NumberFormatter, object CursorUtil, object BaseConverter.

    data class

    A class for holding data. It gets equals, toString and copy for free. data class UnitDefinition(val name, val symbol, val toBase)

    sealed class

    A closed family of subtypes, all known at compile time. sealed class BasicCalcEvent lists every possible user action.

    companion object

    Members that belong to the class itself, not to instances (like Java static). EvaluateExpressionUseCase.ERROR

    interface

    A contract of functions to implement. FactorialFunction : FunctionExtension implements mXparser's interface.

    Platform behaviours Mantis handles

    • Edge-to-edge: since Android 15, apps draw behind system bars. enableEdgeToEdge() plus navigationBarsPadding() on the bottom bar keep content from hiding under the gesture handle.
    • Orientation lock: screenOrientation="portrait" applies on phones. With targetSdk 36 (Android 16), large screens (≥600dp) ignore it, which is why the layouts are fully adaptive (Stage 15).

    • Haptics: view.performHapticFeedback(KEYBOARD_TAP) asks the OS for a key-click vibration. No permission is needed for this one.

    Jetpack Compose: how the UI is described and redrawn

    In Compose you don't build screens by placing widgets. You write functions that say what the screen should look like for the current state, and Compose redraws whenever that state changes.

    The core idea: UI = f(state)

    Stateresult = "1,234"
    →
    @Composable functionDisplayPanel(result)
    →
    UI treeCard → Box → Text
    →
    Pixels
    When the state changes, Compose re-runs only the affected functions. This is called recomposition.
    AnalogyA composable is like a recipe card, not a cake. You don't modify the cake. You change an ingredient (state) and Compose bakes the parts that changed.

    Composable functions

    @Composable
fun TopHeader(title: String, modifier: Modifier = Modifier) {
    Row(modifier = modifier.fillMaxWidth()) {
        Text(text = title, fontSize = 28.sp, color = MaterialTheme.colorScheme.primary)
    }
}
    • Marked @Composable, named with a capital letter, return nothing (they emit UI).
    • Can only be called from other composables.
    • Take a modifier: Modifier = Modifier parameter by convention so callers can size and position them.

    Layout building blocks

    Column

    Stacks children vertically. Each screen is a Column: display on top, keypad below.

    Row

    Places children horizontally. Each keypad row is a Row of 5 CalcButtons.

    Box

    Overlays children. Used for the "Input" label in the corner with the text bottom-right.

    BoxWithConstraints

    A Box that knows its own max size. AutoSizeText uses it to react to width.

    Surface / Card

    Material containers with colour, shape, elevation (shadow).

    Scaffold

    Page skeleton with slots (bottomBar) and safe innerPadding.

    Modifiers: decorating and sizing

    A Modifier is a chain of instructions applied in order, outermost first.

    modifier
    .padding(4.dp)              // 1. outer gap between keys
    .scale(scale)               // 2. shrink to 0.95 while pressed
    .clickable { … }            // 3. tap handling (area excludes the padding)
    .semantics { contentDescription = label }  // 4. screen-reader label
    Order matters.padding(8.dp).background(Green) leaves a gap outside the green. .background(Green).padding(8.dp) fills green and then pads the content inside it.

    Weight: why the grid always fits any screen

    Weights share space in proportion, so 0.40 : 0.60 is 40% and 60% of the height on any phone, tablet or split-screen.

    Architecture: layers, MVVM, state and Unidirectional Data Flow

    Architecture decides which code is allowed to know about which other code. Good architecture means every piece has one job, and each job lives in one place.

    Clean Architecture layers in Mantis

    Why separate layersDomain code like BaseConverter has no UI, so it can be tested in milliseconds on your PC, reused across features (the Converter reuses the Programmer's BaseConverter), and changed without touching screens.

    MVVM: Model, View, ViewModel

    PartIn MantisAllowed toNot allowed to
    View*Screen.kt composablesDisplay state, send eventsCalculate anything, keep business state
    ViewModel*ViewModel.ktHold state, react to events, call domain, save stateReference Views or Context (it outlives them)
    Modeldomain/ + core/utilPure maths and rulesKnow about UI at all

    State exposure pattern (used in every ViewModel)

    private val _result = MutableStateFlow("")               // writable, private
val result: StateFlow<String> = _result.asStateFlow()  // read-only, public
    StateFlow

    A container that always holds one current value and notifies collectors when it changes. It's like a live variable.

    The underscore pattern

    Only the ViewModel can write _result.value = …. The screen can only read result, so no one else can corrupt the state.

    Events as a sealed class

    sealed class BasicCalcEvent {
    data class OnNumberClick(val number: String) : BasicCalcEvent()
    data class OnOperatorClick(val operator: String) : BasicCalcEvent()
    data class OnExpressionChange(val value: TextFieldValue) : BasicCalcEvent()
    object OnClearClick : BasicCalcEvent()
    object OnDeleteClick : BasicCalcEvent()
    object OnEqualsClick : BasicCalcEvent()
}

    Events that carry data are data classes, and events without data are objects. The ViewModel exposes one entry point, fun onEvent(event), and the compiler checks that when(event) handles every case.

    Unidirectional Data Flow (UDF)

    RememberState down, events up. There's one source of truth (the ViewModel). The screen never changes the state directly. It asks, and then shows what it's told.

    Use cases

    A use case is a class that performs exactly one business action. Mantis has two:

    • EvaluateExpressionUseCase: text expression → number (shared by Basic and Scientific).
    • ConvertUnitUseCase: value + units → converted text.

    Both define operator fun invoke(...), so a ViewModel calls them like functions: convertUnitUseCase(input, category, from, to). Simpler logic lives in plain objects (BaseConverter, ScientificFunctions, UnitDefinitions).

    Surviving process death with SavedStateHandle

    Coroutines and threading: never freeze the screen

    ConceptMeaning

    Three safety mechanisms around evaluation

    1. Stale-result guard

    If you keep typing while a calculation runs, the old answer arrives for an expression that no longer exists. It's discarded when the text has changed.

    2. Global lock

    mXparser's DEG/RAD mode is a global setting. synchronized(LOCK) makes "set mode + calculate" atomic, so Basic and Scientific can't interleave.

    3. Length limit

    Expressions over 200 characters are rejected. Long chains of + and − get slow in mXparser, and this keeps every calculation under a second.

    2. "AND": applyOperator: no pending op, so accumulator = 12, pendingOperator = "AND", operand reset, replaceOnNextDigit = true. Input shows 12 AND.
    3. "1", "0": operand = 10, operandTyped = true. Input shows 12 AND 10.
    4. "=": equals() → compute(12, AND, 10) = 8 → resultValue = 8, operand = 8, operator cleared. Output shows 8.
    5. Switching the pill to BIN: SetBase(2) re-formats everything. Input 1000, Output 1000.

    Edge rules worth knowing

    • Chaining: 5 AND 3 OR 1 = computes left to right: (5 AND 3) = 1, then 1 OR 1 = 1.
    • "=" with nothing typed after the operator: uses the left value for both sides (5 AND = → 5 AND 5).
    • NOT is unary: it applies to the current operand immediately.
    • Overflow: a digit that would exceed 64 bits is ignored (parse returns null).
    • Leading zeros are trimmed ("007" → "7").
    • Read-only display: OnExpressionChange is ignored, so keys are the only input. The "." key is permanently disabled (integers only).
    • Process death: all 8 state variables are saved in refresh(), even mid-operation.

    refresh(): one place builds the display

    Every event ends with refresh(), which derives all visible values from the internal state (expression text, input string, current value, result) and saves it. Having a single place to derive output means the screen can never show an inconsistent mix.

    Anatomy of a ViewModel test

    class BasicViewModelTest {
    @get:Rule val mainDispatcherRule = MainDispatcherRule()   // 1. replace Android's main thread
    private lateinit var viewModel: BasicViewModel

    @Before fun setup() {                                     // 2. fresh object before each test
        License.iConfirmNonCommercialUse("Kush")
        viewModel = BasicViewModel(EvaluateExpressionUseCase(Dispatchers.Unconfined), SavedStateHandle())
    }

    @Test fun `large result can be reused in the next calculation`() {
        type("1000+234"); equals()                            // 3. Arrange + Act
        assertEquals("1,234", viewModel.result.value)        // 4. Assert
    }
}
    Arrange, Act, Assert

    Set up the state, perform the action, check the outcome. Every test has this shape.

    MainDispatcherRule

    Dispatchers.setMain(UnconfinedTestDispatcher()) before each test and resetMain() after, so viewModelScope.launch runs immediately.

    Why no Hilt in tests

    Constructor injection lets tests build objects by hand with test doubles (Unconfined dispatcher, empty SavedStateHandle).

    Revision sheet: memorise and recall

    Read each prompt and try to answer it out loud before opening it. Active recall is what turns reading into memory.

    Recall cards

    What are the 3 layers and their jobs?
    Screen (draw + forward events) → ViewModel (state + decisions) → Domain (pure calculation). Plus core/ for shared code.
    What does UDF stand for, and its rule?
    Unidirectional Data Flow: state flows down (VM → UI), events flow up (UI → VM).
    Why _result and result?
    Private MutableStateFlow for writing, public read-only StateFlow for the UI, so only the ViewModel can change state.
    ViewModel vs SavedStateHandle?
    ViewModel survives configuration changes. SavedStateHandle survives process death.
    What do the 6 Hilt annotations do?
    @HiltAndroidApp (start), @AndroidEntryPoint (Activity), @HiltViewModel (VM), @Inject constructor (how to build), @Module+@InstallIn (recipe container), @Provides (recipe).
    Why is the dispatcher injected?
    So tests can pass Dispatchers.Unconfined and run "background" work instantly.
    3 safety measures around evaluation?
    Stale-result guard, synchronized(LOCK) for mXparser's global angle mode, a 200-character limit.
    formatResult vs toExpression?
    formatResult has commas (for humans). toExpression has no commas and full precision (fed back to the parser for chaining).
    Why round to 15 significant digits?
    A Double holds ~15–17 digits, and the rest is noise (0.1+0.2=0.30000000000000004).
    When is scientific notation used?
    |x| ≥ 1e15 or |x| < 1e-6 (and not 0).
    How does chaining after "=" work?
    justEvaluated = true. A digit clears and starts new. An operator continues from the result. Scientific: input starting with + - × ÷ ^ ! ) continues.
    How is 2.5! computed?
    rewritePostfix → fact(2.5) → not whole → Gamma(3.5) ≈ 3.3233. Whole n → exact loop. Negative whole → NaN. Above 170 → ∞.
    Why is NOT 0 = FFFFFFFFFFFFFFFF?
    Two's complement: −1 has all 64 bits set. HEX/OCT/BIN show raw bits via toULong(), and DEC shows signed −1.
    Why clamp shift distances?
    Kotlin uses only the low 6 bits of the shift count, so 1 shl 64 == 1. Mantis returns 0 (or −1 for negative >>).
    Programmer state machine variables?
    accumulator, pendingOperator, operand, operandText, operandTyped, replaceOnNextDigit, resultValue (+ activeBase).
    Linear unit conversion formula?
    value × from.toBase ÷ to.toBase (through meters or grams).
    Why is temperature special?
    It uses offsets, not just factors, so it goes through Celsius. Below −273.15 °C → Error.
    Why does the Converter have no "="?
    recalculate() runs after every event, so the output is always live.
    What does AutoSizeText do?
    Shrinks the font by ×0.9 steps until the text fits (or reaches the minimum), hiding intermediate frames.
    Why DisableSoftKeyboard?
    Keeps the cursor usable while preventing the phone keyboard from covering the keypad.
    minSdk / targetSdk / compileSdk?
    26 (oldest supported) / 36 (behaviour rules followed) / 36 (APIs compiled against).
    What does R8 do, and what's the result?
    Removes unused code and resources, obfuscates, optimises: ~11.7 MB → ~1.5 MB.
    What must never be committed?
    Keystores (*.jks), keystore.properties, local.properties, build outputs.
    Order of calls in onCreate?
    installSplashScreen → enableEdgeToEdge → super.onCreate → License → setContent.
    How does a screen get its ViewModel?
    hiltViewModel(), scoped to the navigation destination, so the same instance is reused when you return to the tab.
    What do popUpTo / saveState / restoreState / launchSingleTop do?
    No growing back stack, remember the tab you left, restore it on return, no duplicate of the current tab.
